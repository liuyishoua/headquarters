# 自主目标与工作台执行

指挥中心维护长期目标和下一步策略。Multica 负责原生规划、Project、主任务、规划 Chat 和行动审计；社交工作台负责实际平台业务执行。这三处通过同一个目标、项目和行动关联，不修改 Multica 核心。

## 执行链路

总部所有新平台行动使用工作台受认证 `/api/business/` 接口：读取能力目录、更新目标授权、提交幂等业务任务、查询状态与增量事件。工作台持久记录任务后异步执行，直接读取自行完成；需要模型时沿工作台→Channel→Multica→Channel→工作台取得草稿，再由工作台确认实际操作结果。模型任务的项目关联由总部通过有限认证入口预绑定，不能相信平台消息里的 project 字段。

Channel 保留消息、模型任务和结果留痕，不成为所有业务行动的调度器。旧总部直接 Channel 动作仅保留既有在途任务的核对；新行动不再从两条入口重复下发。原手动阶段目标继续保留，与自主目标分开。

## 账号和授权

同一目标可多选平台、多选每个平台的账号、多选每个账号的操作。业务 skill 描述方法，目标 grant 决定允许的操作。实际执行取工作台可用操作、账号权限与最新目标授权的交集；每项授权独立到期。撤回、暂停或停止后排队任务不能新执行；在途任务保留核对，未知写入不盲重试。

授权范围可指定已有商品、作品、草稿、素材和会话，主动创建咨询会话另外检查明确收件对象与商品卖家。“允许本目标新建资源”只适用于工作台记录的同目标、同账号产物，不等于全部草稿或任意会话。新会话仍需保留该收件人的授权。默认不勾任何操作。

## 持续推进与结果

总部保存目标、决策、动作、真实结果、观察、写入意图和下次检查。无新消息也按时判断有意义的下一步；已归属业务任务的入站消息会回传并唤醒目标，不猜测无归属消息。状态和回传事件同事务保存，事件接收后持久再推进游标；提交回包丢失沿原幂等请求核对，重启不重新发送。

工作台任务是业务执行权威。模型草稿/本地草稿是中间产物；实际平台 ACK 才是操作回执，仍不等于成交。文档目标核对文件、来源和预设必含项；真实业务结果引用本目标实际证据，由用户核实最终交付。等待、暂停、阻碍、到期和额度耗尽均有明确状态，不靠无限新建任务伪装进展。

## 验收范围

新链路报告见 `workbench-integration-review.md`。真实线上只读目标与真实模型+合成平台写验收分开；前者只读用户授权 Leo 主页，后者使用隔离测试身份、临时工作台和零网络平台。没有真实发帖、私信、商品修改或成交测试。历史 `autonomy-*` 报告保留其原范围，不能当新版平台成交证明。
