# 指挥中心原生任务的 Agent 负责人

指挥中心自主目标已由所选的规划 Agent 在 Multica 原生 chat 中执行。此前同步到项目的主单、行动记录和结果记录刻意不填 assignee，避免 Multica 自动分派产生第二套执行；因此项目列表显示“未分派”，与实际规划运行不一致。

现在先以原方式创建记录，再通过既有 UpdateIssue API 设置 `assignee_type=agent` 和目标已记录的 `agent_id`，同时指定 `suppress_run=true`。分派更新有独立持久化 marker，丢失响应时查询已写记录，不重发创建或运行。以后所有指挥中心任务状态同步也设置抑制运行。

仅抑制当前任务不足以阻止子任务完成唤醒父任务，所以在分派之前，关闭该指挥中心记录自己的 `child_done` 系统唤醒；不改工作区全局规则，不修改实际工作台模型任务。规划推进仍由指挥中心执行，账号操作仍须现有工作台授权与真实回执。单据文字明确“所分派 Agent 为规划负责人”，不会把业务操作伪称为该 Agent 的直接平台执行。

此次只回填最新“用咸鱼账号发布一个帖子，就是那种提供山姆购买服务”目标的 21 个已确认指挥中心主单、行动和结果记录。逐一核对项目、层级、marker、已有负责人及自定义唤醒；没有覆盖其他人工责任人，没有更改任务标题、状态、授权或目标检查时间。分派前后原生 task-runs 集合保持相同；没有启动新的模型运行，没有发送消息或发布商品。该目标仍 active，实际规划 Agent 已返回等待发布资料或可用能力的决策；此修复不代替用户完成发布。
